Smart Energy Consumption Analysis and Prediction using Machine Learning with Device-Level Insights

1. INTRODUCTION
This project is about building a system that tracks how much
energy different home appliances consume and predicts future
usage using machine learning.

In most homes, people only get a monthly electricity bill with
no idea which appliance used the most power or when. This
project solves that by giving device-level insights along with
next-hour energy predictions through a web dashboard.

The main goal is to help users understand their energy usage
and take steps to reduce electricity waste.

2. DATASET USED


Dataset  : SmartHome Energy Monitoring Dataset
File     : smart_home.csv

Columns:
  - Date                      : Date of reading
  - Time                      : Time of reading
  - Appliance Type            : Name of the appliance
  - Energy Consumption (kWh)  : Power used in that hour
  - Outdoor Temperature (C)   : Outside temperature
  - Season                    : Season of the reading

Total Appliances : 9
  Air Conditioning, Computer, Dishwasher, Fridge,
  Heater, Microwave, Oven, TV, Washing Machine


3. WHAT WAS DONE - MODULE BY MODULE


 WEEK 1-2 : Data Collection and Preprocessing --

  - Loaded the CSV file and checked its structure
  - Checked for missing values, duplicates, and data types
  - Plotted total energy consumption by appliance
  - Plotted average consumption by season
  - Checked how temperature affects energy usage
  - Combined Date and Time into one timestamp column
  - Set timestamp as the index for time series use
  - Filled missing values using forward fill method
  - Resampled data into hourly and daily formats
  - Saved processed files:
      smart_home_time.csv
      smart_home_hours.csv
      smart_home_daily.csv
  - Applied MinMaxScaler to normalize energy values
  - Split into 80% train and 20% test sets


 WEEK 3-4 : Feature Engineering and Baseline Model --

  Feature Engineering:
  - Extracted hour, day, weekday, month from timestamp
  - Created lag_1 (previous hour value)
  - Created lag_24 (value from 24 hours ago)
  - Created rolling_mean_24 (average of last 24 hours)
  - Saved separate train/test files per appliance

  Baseline Model (Linear Regression):
  - Trained one Linear Regression model per appliance
  - Evaluated using MAE and RMSE
  - Plotted actual vs predicted for each appliance
  - Saved each model as a .pkl file


WEEK 5-6 : LSTM Model and Evaluation --

  Global LSTM (all devices combined):
  - Built LSTM with 64 and 32 units
  - Added Dropout layers to prevent overfitting
  - Used Adam optimizer and MSE loss
  - Used EarlyStopping with patience=5
  - Compared results with Linear Regression

  Device-Level LSTM (per appliance):
  - Trained separate LSTM model for each appliance
  - Each appliance has its own scaler
  - Used last 24 hours as input to predict next hour
  - Saved lstm_{device}.h5 and scaler_{device}.pkl
    for all 9 appliances


 WEEK 7-8 : Dashboard and Web Application --

  Backend (app.py - Flask):
  - Built 9 API endpoints to serve data and predictions
  - Loads smart_home_time.csv and all trained models
  - Returns JSON responses for all frontend requests

  Frontend (HTML + CSS + JS):
  - index.html  : page structure only
  - style.css   : all styling and dark theme
  - script.js   : all JavaScript and API calls

  Dashboard has 4 pages:
  - Dashboard   : stat cards, trend chart, device pie chart
  - Devices     : per-device chart, ranking table
  - Predictions : next-hour forecast per device with level
  - Insights    : top consumer info and saving tips

  GET  /api/predict_all    Predictions for all devices
  POST /api/predict        Prediction for one device
  GET  /api/insights       Highest and lowest usage device


5. PREDICTION LEVEL LOGIC

Instead of using fixed cutoff values, I used the standard
deviation of each device to decide if a prediction is
High, Moderate, or Low.

  High     -> prediction is above (mean + std deviation)
  Moderate -> prediction is within mean plus or minus std
  Low      -> prediction is below (mean - std deviation)

  Special case: if std is nearly zero (very stable device
  like Fridge), the band is set to 10% of the mean instead.

This way each device is judged against its own normal
behaviour and not a common threshold.

9. LIMITATIONS

  - The dashboard works on static CSV data only
    (no live sensor connection yet)
  - LSTM predictions tend to stay close to the average
    so extreme values are harder to predict
  - Model retraining has to be done manually
  - No login or user authentication on the web app
